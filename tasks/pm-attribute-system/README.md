# 笔试题：给每个 SYB 成员画一张「角色卡」—— 设计一套组织 RPG 属性系统

> **方向**：产品经理（开放式系统设计 + vibe coding 原型）
> **交付物**：一份机制设计文档（Markdown） + 一个可交互原型
> **建议耗时**：10–18 小时（须在 fork 后 72 小时内提交 PR）
> **关联岗位**：[产品经理 · 武汉](https://syb.team/who-we-want/)
> **系列**：Project Genesis · 第二章（[第一章：规则](https://github.com/syb-team/Genesis)）

## 背景：创世纪·第二章

你已经读过 [SYB 的招聘站](https://syb.team)，也大概知道我们想造什么样的组织。

如果你做过 [Project Genesis 第一章](https://github.com/syb-team/Genesis)，你写下了一套**规则**——谁能加入、谁说了算、好事怎么被看见、蠢事怎么被纠偏。规则是组织的「宪法」。

但宪法之下，每个活生生的人，在这个游戏里到底是什么**角色**？

游戏里，每个角色都有一张**角色卡**：血量（HP）、魔力（MP）、经验值、等级、技能树、职业、天赋、buff/debuff……这张卡刻画了它「现在是什么状态、擅长什么、还能撑多久、成长到哪了」。

**第二章的问题是：SYB 的每个成员，要不要也有这样一张卡？如果有，它该长什么样？**

## 你的核心任务

> **你是 Project Genesis 的属性架构师。请用「RPG 角色卡 / 属性系统」的设计思维，为 SYB 设计一套「成员的能力与状态」系统——并 vibe coding 出一个能跑的原型。**

「RPG 属性系统的思维」**不是**给 HR 系统贴上「血量=绩效、魔力=积极性、技能树=晋升路径」的皮肤——那是最低级的隐喻搬运，我们没兴趣。我们想看的是：你能不能从 RPG 属性系统几十年的**底层设计原理**里——资源的稀缺与恢复、成长的曲线与门槛、职业分化与互补、临时状态与持久特质、可见与不可见——提炼出可迁移到「一个真实运转的远程研发团队」的东西。

然后，把它落到一张**真的对 SYB 成员有意义、且不会异化**的角色卡上，并且**亲手用 AI 把它做成一个能点、能看、能演示的原型**。

## 你必须正面回应的五件事

开放题，没有标准答案，但下面五个每一个你都得给出明确立场和论证——端水的、四平八稳的、面面俱到却没主张的，在我们这儿等于没答。

### 1. 翻译，而不是搬运
你具体借鉴了哪几条 RPG 属性系统原理？一条一条说清楚：它在游戏里本来是干嘛的（HP / MP / EXP / 技能树 / 职业 / 天赋 / buff / debuff / 装备……挑你最看重的几条），你把它翻译成了 SYB 角色卡上的什么，为什么这条适合「远程、扁平、异步、只看产出」的我们。要迁移的**精度**，不要术语的密度。

### 2. 不属性化的保留地（本题灵魂之一）
属性系统的本质是「把人量化、可比较」。而 SYB 反复说「不把人当耗材 / 不为 KPI 而 KPI」。**请直面这个比第一章更尖锐的张力**——这次你量化的直接就是「人本身」。所以：哪些关于一个人的东西，你**坚决不给属性、不给数值、不放进卡里比较**？你凭什么相信，这张卡不会变成一张更精致的绩效考评表？—— 这是本题最重的一关，我们重点看你怎么答。

### 3. 属性是一套经济系统
HP、MP 这些不是静态标签，是**会涨会跌、会获取会消耗、会稀缺会通胀的资源**。请讲清楚：你的属性怎么获取（做什么事涨）、怎么消耗（做什么事掉）、怎么恢复（掉了怎么回血）、会不会通胀（人人满级了怎么办）、稀缺性怎么设计。并且预测一个二阶后果：18 个月后，这套属性经济哪里最可能先崩？

### 4. 崩坏剧本（聪明人怎么钻你的空子）
任何属性系统都会被博弈。聪明人会怎么钻你这套卡的空子？刷分？属性歧视（只跟高 HP 的人玩）？动机挤出（为了涨 MP 而做事，忘了为什么做事）？Goodhart 定律（一旦某属性变成指标，它就不再是好指标）？挑一个你最担心的崩坏，设计你的反制——或坦然承认「这个空子我堵不上，理由是 X」。

### 5. 角色卡原型（vibe coding，不是 PPT）
光说不练，在我们看来就是 PPT。请用 AI（Claude / Cursor / v0 / 任意工具）亲手做出一个**可交互的角色卡原型**：能展示一个 SYB 成员的属性面板、能看到至少一条「行为 → 属性变化」的回路（比如完成一个 PR，某个属性怎么动）。技术不限（Figma 高保真 / codepen / AI 建站 / 一个小 web app 都行），但必须**能给链接、能演示**。附上设计日志：AI 怎么用的、你让它做了什么、你采纳了什么、拒绝了什么、推翻过什么。

## 交付物

两样：

**① 一份机制设计文档**（Markdown，文档优先，不要 PPT）。建议结构如下，但**结构本身也是考察项**——你可以推翻它、重构它，只要你能说明理由：

```
1. 我读懂的 SYB（3 句话以内，证明你不是泛泛而谈）
2. 设计目标与「不属性化的保留地」（含你刻意不放进卡的边界 + 理由）
3. 角色卡设计（借鉴了什么 RPG 原理 → 翻译成卡上的什么 → 为什么）
4. 属性经济系统（获取 / 消耗 / 恢复 / 通胀 / 稀缺 + 一个 18 个月后的崩点）
5. 崩坏剧本（聪明人怎么钻空子 + 你的反制）
6. 原型（链接 + 截图 + 设计日志：AI 怎么用、采纳/拒绝了什么）
7. 我注入的价值观（每条价值观 ↔ 卡上的具体机制）
8. 设计日志（推翻过哪些方案？我留下的遗憾是什么？）
```

**篇幅**：3000–6000 字为佳。重密度，不重字数。

**② 一个可交互原型链接**（贴在文档第 6 节，也贴在 PR 描述里）。
